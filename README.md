# outline-docs

Скилл для [Claude Code](https://claude.com/claude-code): база знаний [Outline](https://www.getoutline.com/) прямо из чата — найти документ, написать инструкцию, выдать клиенту ссылку, проверить, что именно он увидит.

```
Вы:     клиенту нужна инструкция по подключению обмена
Claude: Нашёл «Подключение к обмену заказами» в коллекции «Инструкции».
        Текст, который увидит получатель: … (показывает целиком)
        Выдать публичную ссылку?
Вы:     да
Claude: https://wiki.example.com/s/8f2c…  — открывается без входа в Outline.
```

```
Вы:     что мы вообще отдали клиентам?
Claude: Выдано 6 ссылок. Две не открывали ни разу, одна ведёт на черновик —
        стоит проверить: #3 «Регламент обновления», 47 просмотров, последний вчера.
```

## Как устроено

```
чат Claude Code  →  SKILL.md (правила)  →  scripts/outline.ts  →  Outline API
                                        ↘  scripts/guard.ts (проверка текста)
```

CLI на [Bun](https://bun.sh) и TypeScript: нулевые зависимости, нативный `fetch`, строгая типизация. Работает и без Claude — как обычная утилита командной строки.

## Возможности

| Область | Что умеет |
|---|---|
| Навигация | коллекции, структура коллекции, список и поиск документов, чтение с выгрузкой в файл |
| Документы | создание по редакционному стандарту, правка и дописывание, публикация черновика, перемещение, архивация, удаление, экспорт в Markdown |
| Ссылки клиентам | выдать публичную ссылку (с вложенными документами или без), увидеть все выданные ссылки с просмотрами и последним обращением, отозвать |
| Редактор | документ пишется по структуре «зачем → что понадобится → шаги → проверка → если не получилось → куда обращаться», а не как надиктовано |
| Проверка | реквизиты доступа, токены, платёжные и персональные данные, внутренние адреса, самооговор, обещания без условий — строго для всего, что уходит наружу |
| Подтверждение | ни одно изменение не уходит без предпросмотра: команда без `--yes` показывает точный текст и выходит |
| Автообновление | скилл сам подтягивает обновления раз в сутки, не затирая локальные правки |

Три состояния документа различаются явно: **черновик** виден только автору, **опубликованный** — команде по правам коллекции, **доступный по ссылке** — любому, у кого есть ссылка, без входа. Строгая проверка текста включается там, где он действительно уходит наружу: при выдаче публичной ссылки и в коллекциях, помеченных как клиентские.

## Установка

Нужны [Claude Code](https://claude.com/claude-code) и [Bun](https://bun.sh) ≥ 1.2.

```bash
git clone https://github.com/33solutions/outline-docs.git ~/.claude/skills/outline-docs
```

## Настройка

```bash
mkdir -p ~/.outline
cp ~/.claude/skills/outline-docs/config.example.json ~/.outline/config.json
```

Токен берётся в Outline: **Настройки → API → New token**. Он привязан к вашей учётной записи и даёт ровно её права.

```json
{
  "default": "work",
  "instances": {
    "work": {
      "url": "https://outline.example.com/",
      "apiKey": "…",
      "defaultCollection": "Инструкции",
      "clientCollections": ["Документация для клиентов"]
    }
  }
}
```

Переменные `OUTLINE_URL`, `OUTLINE_API_KEY`, `OUTLINE_INSTANCE` переопределяют конфиг. Проверка: `bun ~/.claude/skills/outline-docs/scripts/outline.ts whoami`.

## Как просить Claude

- «найди инструкцию по подключению обмена и дай ссылку клиенту»
- «напиши инструкцию по настройке уведомлений, коллекция Инструкции»
- «обнови раздел про статусы в документе <ссылка>»
- «какие ссылки мы выдали наружу и что по ним смотрели?»
- «отзови ссылку на регламент обновления»
- «выложи результат работы по задаче #1234 в базу знаний»

Перед любым изменением Claude показывает, что именно уйдёт в Outline, и ждёт подтверждения.

## CLI

```bash
R=~/.claude/skills/outline-docs/scripts/outline.ts

bun $R collections
bun $R collections create --name "Раздел" --permission read --no-sharing --icon terminal --yes
bun $R tree --collection "Инструкции"
bun $R search "подключение обмена"
bun $R doc <id|url> --full --out /tmp/doc.md

bun $R create --collection "Инструкции" --title "Тема" --file /tmp/doc.md          # предпросмотр
bun $R create --collection "Инструкции" --title "Тема" --file /tmp/doc.md --publish --yes
bun $R update <id> --file /tmp/new.md --yes
bun $R update <id> --file /tmp/add.md --append --yes
bun $R publish <id> --yes

bun $R share <id>                 # предпросмотр: что увидит получатель
bun $R share <id> --yes           # выдать публичную ссылку
bun $R shares                     # что выдано: просмотры, последнее обращение
bun $R unshare <shareId> --yes    # отозвать

bun $R scan --file /tmp/doc.md    # проверить текст отдельно
```

Полный список — `bun $R help`.

## Безопасность

**Подтверждение.** `create`, `update`, `publish`, `share`, `move`, `archive`, `delete` требуют `--yes`. Без него печатается полный предпросмотр — ровно тот текст, который уйдёт, — и команда завершается. Это свойство инструмента, а не договорённость с моделью.

**Проверка содержимого** (`scripts/guard.ts`, общий модуль со скиллом [redmine-time](https://github.com/33solutions/redmine-time)): пароли и токены, приватные ключи, строки подключения, номера карт, СНИЛС и паспортные данные — запрет всегда; внутренние адреса и пути, самооговор, оценки людей, обещания без условий, внутренняя экономика — запрет для всего, что видит клиент. Планка выбирается по месту: документ в клиентской коллекции и любая публичная ссылка проверяются строго, внутренние документы — мягче.

**Токен** хранится только локально в `~/.outline/config.json`, не печатается в вывод и исключён из репозитория через `.gitignore`.

## Файлы

| Путь | Назначение |
|---|---|
| `SKILL.md` | инструкции для модели: роль редактора, протокол подтверждения, сценарии |
| `scripts/outline.ts` | CLI: навигация, документы, ссылки, проверка |
| `scripts/guard.ts` | проверка текста на компрометацию |
| `references/editorial.md` | редакционный стандарт документов базы знаний |
| `references/safety.md` | что нельзя публиковать и как переформулировать |
| `references/api.md` | особенности Outline API и подводные камни |

Состояние: `~/.outline/config.json` (профили), `cache.json` (коллекции, TTL 6 часов), `state.json` (проверка обновлений).

## Разработка и релизы

```bash
bun scripts/selftest.ts               # проверки разбора ссылок и правил, без обращения к Outline
bun scripts/audit-repo.ts --history   # сканер утечек по файлам и истории репозитория
bunx tsc --noEmit
```

CI прогоняет это на каждый push и pull request. Релиз выпускается сам: достаточно изменить `VERSION` в `main` — Actions проверят код, соберут архив и создадут запись в Releases с заметками из `CHANGELOG.md`.
