# Outline: база знаний, инструкции и ссылки клиентам

Скилл ведёт базу знаний как редактор, а не как транспорт: формулирует документы по стандарту, проверяет их перед тем, как они станут видны клиенту, и ничего не отправляет без подтверждения.

```bash
bun ~/.claude/skills/outline-docs/scripts/outline.ts <команда> [флаги]
```

`... help` — полный список команд. Инстансы и коллекции по умолчанию берутся из `~/.outline/config.json`, профили видно командой `... instances`.

## Железные правила

1. **Ничего не меняется без подтверждения.** `create`, `update`, `publish`, `share`, `move`, `archive`, `delete` без `--yes` печатают полный предпросмотр и выходят. Порядок: собрать текст → команда без `--yes` → показать пользователю дословно → получить «да» → повторить с `--yes`.
2. **Три разных по риску действия — три разные планки.**
   - *черновик* (`create` без `--publish`) — проверка по внутренней планке;
   - *публикация* (`publish`, `create --publish`) — по клиентской: документ становится частью базы знаний;
   - *ссылка наружу* (`share`) — по клиентской и с явным предупреждением: по ссылке документ открывается **без входа в Outline**, любому, у кого она есть.
3. **Перед выдачей ссылки читай документ целиком.** Предпросмотр `share` показывает текст, который увидит получатель. Если внутри есть внутренние детали — сначала правка, потом ссылка.
4. **Тексты — по стандарту**, а не «как надиктовали»: см. `references/editorial.md`. Пользователь даёт суть, скилл пишет документ.
5. **Отзыв ссылки необратим** и требует отдельного `--yes`: получатель теряет доступ сразу.
6. **Удаление** требует `--yes`, а `--permanent` — отдельного подтверждения: документ не восстановится.

## Что важно знать про Outline

- Документ бывает **черновиком** (виден только автору), **опубликованным** в коллекции (виден команде по правам коллекции) и **доступным по ссылке** (виден всем, у кого есть ссылка). Это три независимых состояния.
- Публичная ссылка живёт отдельно от документа: она выдаётся, у неё считаются просмотры, её можно отозвать, не трогая сам документ.
- Коллекция задаёт права: если у коллекции выключен обмен ссылками, `share` вернёт отказ — это настройка администратора, а не ошибка скилла.
- Текст документов — Markdown. Заголовки, списки, таблицы, ссылки на другие документы через их URL.

## Роль редактора

Когда пользователь говорит «напиши инструкцию», «опиши процесс», «выложи это клиенту» — он даёт материал, а не готовый текст:

1. **Посмотреть, что уже есть.** `search` по теме: возможно, документ существует и нужно обновить его, а не плодить второй.
2. **Понять читателя.** Инструкция для клиента и внутренний регламент пишутся по-разному: клиенту не нужны наши внутренние названия контуров и процессы.
3. **Уточнить недостающее** — не больше 2–3 вопросов: для кого документ, что читатель должен уметь после него, что считается выполненным.
4. **Написать по структуре** из `references/editorial.md`: зачем → что понадобится → шаги → проверка результата → что делать, если не получилось → к кому обращаться.
5. **Показать и согласовать**, затем опубликовать или выдать ссылку.

## Сценарии

**Найти и дать ссылку клиенту**
```bash
... search "подключение к обмену"
... doc <id> --full                      # прочитать целиком и убедиться, что документ годится
... share <id>                           # предпросмотр: текст, который увидит получатель
... share <id> --yes                     # выдать ссылку
```
Клиенту отдавай только ссылку вида `.../s/…` — внутренний адрес `/doc/…` требует входа в Outline и ему бесполезен.

**Написать инструкцию**
```bash
... create --collection "Инструкции" --title "Подключение к обмену" --file /tmp/doc.md
... create --collection "Инструкции" --title "…" --file /tmp/doc.md --publish --yes
```
Длинный текст передавай файлом — так не ломается Markdown и кавычки.

**Обновить существующий документ**
```bash
... doc <id> --out /tmp/current.md       # выгрузить текущий текст
... update <id> --file /tmp/new.md       # предпросмотр замены
... update <id> --file /tmp/add.md --append --yes   # дописать раздел в конец
```

**Проверить, что выдано наружу**
```bash
... shares                               # все ссылки: просмотры, последнее обращение
... shares --document <id>
... unshare <shareId> --yes              # отозвать
```
Это же — ответ на вопрос «что клиент вообще видит».

**Навигация**
```bash
... collections
... tree --collection "Инструкции"
... docs --collection "Инструкции" --limit 30
```

## Связка с Redmine

Если установлен скилл `redmine-time`, работают оба направления:

- **Из задачи — в базу знаний.** Работа по задаче закончена, результат нужен как инструкция: прочитай задачу (`redmine.ts issue <N>`), напиши документ по стандарту (не копируя переписку и внутренние детали), создай его и выдай ссылку.
- **Из базы знаний — в задачу.** Получив публичную ссылку, добавь её в задачу комментарием через `redmine.ts comment <N> --text-file …` — с тем же протоколом подтверждения. В комментарии давай ссылку `/s/…`, а не внутреннюю.

Ссылки на документы внутри Redmine и наоборот — обычные URL; пиши их полностью, чтобы читатель не искал.

## Проверка перед отправкой

Автоматически проверяется каждый текст: реквизиты доступа и токены, строки подключения, платёжные и персональные данные, внутренние адреса и пути, самооговор, оценки людей, обещания без условий, внутренняя экономика. Перечень и порядок работы с находками — `references/safety.md`.

```bash
... scan --file draft.md                 # проверить черновик отдельно
... scan --file draft.md --audience internal
```

Если проверка остановила публикацию — правь текст, а не обходи её. `--override-guard` применяется только по явной просьбе пользователя, и об этом говорится вслух. Если документ с реквизитами уже опубликован или по нему выдана ссылка: сначала отозвать ссылку, потом править текст, потом менять реквизиты — Outline хранит историю правок.

## Настройка

Конфиг `~/.outline/config.json`, образец — `config.example.json`. Токен: в Outline → **Настройки → API** → создать токен; вписывает его пользователь сам. Проверка: `... instances`, затем `... whoami`.

Поля профиля: `defaultCollection` — куда складывать новые документы, `clientCollections` — коллекции, где любой документ считается клиентским.

## Обновление скилла

Обновляется сам раз в сутки при старте сессии (hook `SessionStart`). Вручную:

```bash
bun ~/.claude/skills/outline-docs/scripts/update.ts --apply
```

Локальные правки в папке скилла не затираются.

## Диагностика

- `authentication_required` — токен неверен или отозван: перевыпустить в *Настройки → API*.
- `authorization_error` — прав учётной записи не хватает: закрытая коллекция или запрет на обмен ссылками.
- `not_found` — документ удалён, в корзине или принадлежит другому пространству.
- `validation_error` — чаще всего пустой текст или несуществующая коллекция.
- Справочник коллекций кэшируется на 6 часов; после изменений в Outline — `--no-cache`.

Особенности API — `references/api.md`. Редакционный стандарт — `references/editorial.md`. Правила проверки — `references/safety.md`.
