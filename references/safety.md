# Проверка перед отправкой: что нельзя отправлять и как переформулировать

Документ в базе знаний живёт дольше переписки: его читают через годы, на него дают ссылки клиентам, он попадает в поиск и в переписку с третьими лицами. Опубликованный документ считается опубликованным навсегда. Поэтому проверка идёт в два слоя.

**Слой 1 — автоматический.** Модуль `scripts/guard.ts` проверяет каждый уходящий текст: название и тело документа — при создании, публикации и выдаче ссылки. Находки класса «запрет» останавливают отправку; снять запрет может только явный `--override-guard`, и это осознанное решение пользователя, а не модели.

**Слой 2 — редакторский.** Формальные правила не видят смысла. Перед показом текста пользователю модель сама проверяет его по разделу «Что проверяет человек» ниже.

Проверить текст отдельно:

```bash
bun scripts/outline.ts scan --file draft.md                  # аудитория по умолчанию — клиент
bun scripts/outline.ts scan --file draft.md --audience internal   # мягче: внутренний документ
```

Коды возврата: `0` — чисто или только предупреждения, `2` — отправлять нельзя.

## Запрет: не уходит наружу никогда

| Категория | Примеры | Что делать |
|---|---|---|
| Учётные данные | пароль, `password=`, `Пароль от админки: …` | Передать через менеджер секретов, в задаче — ссылка на него |
| Ключи и токены | `ghp_…`, `sk-…`, `AKIA…`, JWT, `Bearer …` | Убрать из текста и **отозвать**: попав в трекер, ключ скомпрометирован |
| Приватные ключи | `-----BEGIN … PRIVATE KEY-----` | Перевыпустить ключевую пару |
| Строки подключения | `mongodb://user:pass@host`, `Usr="…";Pwd="…"` для 1С | Оставить хост и базу, учётные данные — в хранилище |
| Платёжные данные | номер карты (проверяется по Луну) | Достаточно последних четырёх цифр |
| Персональные данные | СНИЛС, паспорт | Ссылка на кадровую или учётную систему |

## Запрет в клиентских задачах, предупреждение во внутренних

Аудитория определяется действием: черновик проверяется как внутренний документ, публикация и выдача ссылки — как клиентский. Флаг `--audience` переопределяет это в команде `scan`.

| Категория | Почему опасно | Как переформулировать |
|---|---|---|
| Внутренние IP и имена узлов | карта инфраструктуры в документе живёт вечно и уходит по ссылке | «сервер приложений», «тестовый контур» |
| Самооговор | признание вины в трекере — готовое доказательство в споре | факт → влияние → что сделано → что предотвращает повтор |
| Оценки людей | репутационный и юридический риск | наблюдаемый факт и следствие для работы |
| Обещания без основания | срок без условий превращается в обязательство | «при выполнении X к дате Y — результат к дате Z» |
| Внутренняя экономика | себестоимость, маржа, ставки | обсуждать во внутреннем проекте |
| Другие клиенты | нарушение конфиденциальности третьей стороны | убрать упоминание полностью |

## Предупреждение: решает автор

Локальные пути (`C:\Users\…`), телефоны, адреса почты, ИНН. Не блокируются, но в предпросмотре показываются: чаще всего это следы черновика, а не нужная информация.

## Что проверяет человек (и модель до него)

Формальный сканер этого не видит — проверяется смыслом:

1. **Не признаём вину.** Есть разница между «сбой из-за нашей ошибки» и «сбой возникал на заказах без артикула; добавлена проверка». Второе — тоже правда, но без правовых последствий.
2. **Не даём обещаний, которых не контролируем.** Любой срок — с условием, от которого он зависит.
3. **Не оцениваем людей.** Ни заказчика, ни его подрядчиков, ни коллег. Только наблюдаемые факты.
4. **Не выносим внутренние разногласия.** Споры о подходе решаются до публикации; в документ идёт решение.
5. **Не пересказываем переписку и не цитируем третьих лиц** без необходимости: краткий факт и ссылка на источник.
6. **Проверяем адресность.** «Требуется от вас» — с именем роли и датой, иначе это не запрос, а пожелание.
7. **Проверяем проверяемость.** Каждое утверждение «сделано» должно сопровождаться способом убедиться.
8. **Смотрим на тон.** Сообщение читают в момент, когда что-то сломалось. Нейтральная формулировка экономит переписку.

## Порядок работы с находками

1. Сканер нашёл запрет → **текст правится**, а не обходится. Отправка остановлена.
2. Находка ложная (например, обсуждается формат токена, а не сам токен) → сказать об этом пользователю и только с его согласия использовать `--override-guard`. Молча обходить проверку нельзя.
3. Предупреждения → показать пользователю вместе с предпросмотром, предложить правку.
4. Секрет уже попал в документ → сообщить пользователю немедленно. Порядок: отозвать публичную ссылку, затем править текст, затем менять сами реквизиты. Outline хранит историю правок, поэтому правка текста сама по себе не закрывает утечку.
